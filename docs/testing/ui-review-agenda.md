# Вопросы для обсуждения перед исправлениями

> Никакие решения ниже не приняты — задача аудита read-only. Каждый пункт требует обсуждения с продуктом/дизайном перед любыми правками кода.

## Мешает демонстрации

Пунктов нет. По итогам этого визуального аудита UI-P1 (блокирующих демонстрацию/основное действие) не найдено — согласуется с выводом `docs/testing/release-readiness.md` о том, что P0/P1 в прототипе на текущий момент отсутствуют.

## Общие компоненты

Затрагивают компонент, используемый на нескольких/всех экранах — исправление в одном месте отражается везде.

- **UI-003** (P3) — несогласованная высота `ui-input`/`ui-select` (46px) и `ui-button` (40px/32px) в одной строке.
  - Варианты: привести компактные контролы к 40px по токену; либо оставить 46px и подобрать кнопки такой же высоты для toolbar-контекста; либо задокументировать как осознанный «compact toolbar variant».
  - Риск изменения: MEDIUM — глобальный компонент, требует сверки с Figma control heights перед правкой.
  - Рекомендация: **обсуждать** с дизайном (нужна сверка с Figma, не только визуальное решение).
- **UI-005** (P2) — модалка `#assign-modal` без `aria-modal`, Escape и focus-management.
  - Варианты: добавить focus trap + Escape по аналогии с уже реализованным `#filters-drawer`; либо использовать сторонний a11y-паттерн, если появятся другие модалки.
  - Риск изменения: MEDIUM — затрагивает единственную существующую модалку, но при доработке важно не сломать текущий flow назначения/переназначения.
  - Рекомендация: **обсуждать** приоритет фикса (это единственный найденный accessibility-пробел такого уровня в общих компонентах).
- **UI-006** (P2) — индикатор уведомлений всегда включён.
  - Варианты: скрыть точку по умолчанию до появления реальной модели уведомлений; либо реализовать минимальную заглушку-состояние («нет новых»).
  - Риск изменения: LOW.
  - Рекомендация: **обсуждать** — решение зависит от того, планируется ли реализация уведомлений в ближайших этапах.
- **UI-009** (P3) — таблицы (`ui-data-table`) требуют горизонтального скролла на ≤1024/390px из-за `min-width:960px`.
  - Варианты: признать горизонтальный скролл осознанным admin-паттерном для мобильных (изменений не требуется, только продуктовое решение зафиксировать); либо спроектировать карточный вид строк для узких экранов (высокий объём работ).
  - Риск изменения: MEDIUM (если менять) / отсутствует (если оставить как есть).
  - Рекомендация: **проверить вручную** на реальном мобильном устройстве/эмуляторе перед решением — в этой сессии визуально не воспроизводилось.

## Только один экран

- **UI-001** (P2) — экран создания обращения (`#/flow`) использует legacy-дизайн (`styles/main.css`), полностью отличный от остальной системы `ui-*`.
  - Варианты: полный редизайн экрана на `ui-*` компонентах отдельным этапом; либо осознанно оставить как временный «демо AI-обработки» с явной пометкой в интерфейсе.
  - Риск изменения: HIGH — самый объёмный из найденных пунктов, пересекается с существующим DEF-008 (hardcoded ID при создании).
  - Рекомендация: **обсуждать** — вероятно, требует отдельного этапа/спринта, а не точечного фикса.
- **UI-002** (P3) — нет активного пункта меню на `#/flow`.
  - Варианты: подсвечивать «Обращения» как родительский раздел; оставить без подсветки как у отдельного flow-процесса.
  - Риск изменения: LOW.
  - Рекомендация: **обсуждать** в связке с UI-001 (если экран будет полностью переделан, вопрос решится сам).
- **UI-004** (P2) — нестилизованный `dl`/`dt`/`dd` в блоке «Контактная информация» карточки клиента.
  - Варианты: заменить разметку на существующий `.ui-meta-list__item/__label/__value` (минимальный объём правок, CSS менять не требуется).
  - Риск изменения: LOW.
  - Рекомендация: **обсуждать** приоритет включения в ближайший фикс-пак — простое, локальное, невизуально рискованное исправление.
- **UI-010** (P4) — дублирование статуса/приоритета/SLA между header и сайдбаром карточки обращения.
  - Варианты: оставить как есть (обоснованное дублирование для разного уровня детализации); либо убрать дублирование из сайдбара.
  - Риск изменения: LOW.
  - Рекомендация: **оставить** — минорный косметический момент, не создающий путаницы по сути (значения идентичны).

## Адаптивность

- **UI-007** (P3) — разный UX-паттерн мобильных фильтров: drawer на «Обращениях» vs построчный перенос на «Клиентах»/«Шаблонах».
  - Варианты: унифицировать на drawer-паттерне везде; унифицировать на построчном переносе везде; оставить осознанно разным, если на «Обращениях» больше фильтров и это оправданно.
  - Риск изменения: MEDIUM — синхронная правка нескольких экранов.
  - Рекомендация: **обсуждать** с продуктом/дизайном, какой паттерн считать целевым.
- **UI-009** (P3) — см. выше в разделе «Общие компоненты» (таблицы и горизонтальный скролл).
  - Рекомендация: **проверить вручную** на реальном устройстве 390px перед принятием решения.

## Figma-расхождения

Эти пункты касаются токенов/компонентов и требуют сверки с дизайн-командой/Figma, а не немедленного фикса:

- **`--color-focus-ring`** (`docs/design-tokens.md` §12) промаркирован как «unconfirmed», используется глобально для всех `:focus-visible` состояний (кнопки, поля, табы, nav item, settings-item). Рекомендация: **обсуждать** — нужно официальное подтверждение цвета фокус-кольца в Figma.
- **Control heights 46px vs 40px** (см. UI-003) — возможно, в самом Figma Kit «Input»/«Select» имеют высоту, отличную от «Button M», и несоответствие заложено изначально в токенах, а не является ошибкой реализации. Рекомендация: **обсуждать** со сверкой оригинальных Figma-компонентов Input/Select/Button.
- **Corner smoothing 50%** в Figma не воспроизводится обычным CSS `border-radius` (задокументированное ограничение в `docs/design-tokens.md` §6). Рекомендация: **оставить** — известное техническое ограничение CSS, не требует решения в рамках этого прототипа.
- **Расхождение документации и кода:** `docs/ui-component-inventory.md` описывает старую версию прототипа на классах `.btn`/`.table`/`.select`/`.badge` (`styles/main.css`), тогда как 8 из 9 экранов уже используют актуальную токен-систему `ui-*`. Это **не UI-дефект интерфейса**, а расхождение документации с кодом. Рекомендация: **обсуждать** обновление документа (вне контекста визуального UI-аудита).

## Доступность

- **UI-005** (P2) — см. «Общие компоненты» выше (модалка без `aria-modal`/Escape/фокуса).
- `#filters-drawer` также не имеет `aria-modal="true"` (только `role="dialog"`), хотя Escape/фокус в нём реализованы корректно — можно исправить малой кровью вместе с UI-005.
  - Рекомендация: **обсуждать** вместе с UI-005 как единый accessibility-фикс-пак для диалоговых паттернов (`ui-modal` + `ui-drawer`).
- Дублирование именования статус-select в карточке обращения (`visually-hidden`-label + `aria-label` одновременно) — не ошибка, но избыточность в разметке.
  - Рекомендация: **проверить вручную** со скринридером — вероятно, не критично, но стоит подтвердить отсутствие двойного объявления имени поля.

## Требуют продуктового решения

- **UI-001** — объём и сроки редизайна экрана создания обращения (`#/flow`) — отдельный этап или входит в текущий scope демо.
- **UI-006** — судьба реального механизма уведомлений (индикатор всегда включён) — зависит от планов по разделу «Уведомления».
- **UI-007** — единый паттерн мобильных фильтров для всех списков — архитектурное решение по UX, влияет на 3 экрана.
- **UI-009** — целевая стратегия для таблиц на мобильных разрешениях (горизонтальный скролл vs карточный вид) — требует продуктового решения о поддерживаемом уровне мобильного UX для admin-панели.
