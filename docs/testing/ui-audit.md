## Проверенные разрешения

Так как браузерный рендеринг недоступен, разрешения оценивались **по правилам `@media` в CSS** (`styles/layout/shell.css`, `styles/pages/*.css`, `styles/components/drawer.css`, `styles/components/modal.css`, `styles/components/button.css`, `styles/components/page-layout.css`). Каждый пункт ниже помечен как **«проверено по коду, не воспроизведено визуально в браузере»**.

| Viewport | Ключевые точки перелома, затронутые на этой ширине | Ожидаемое поведение по коду |
|---|---|---|
| 1440×900 | Нет активных breakpoint (>1280) | Полный desktop layout: развёрнутый sidebar 260px, inline-фильтры, двухколоночные карточки (обращение/клиент), KPI-сетка 4 колонки |
| 1280×800 | `max-width: 1280px` (`appeals-list.css`, `analytics.css`, `settings.css`) | Сужение search/select в toolbar обращений; KPI-сетка аналитики → 2 колонки; каталог настроек → 2 колонки |
| 1024×768 | `max-width: 1024px` (`shell.css`, `appeals-list.css`, `appeal-detail.css`, `page-layout.css`, `client-detail.css`, `analytics.css`, `settings.css`, `button.css`) | Sidebar становится off-canvas drawer (`position:fixed`, `transform:translateX(-100%)`) + гамбургер в хедере; двухколоночные карточки обращения/клиента → одна колонка (сайдбар-карточки уходят вверх через `order:-1`); toolbar обращений оборачивается; кнопки в хедере списка становятся icon-only |
| 390×844 | `max-width: 768px` (только `appeals-list.css`); остальное наследуется от breakpoint 1024 | Toolbar обращений переключается на drawer-паттерн фильтров (кнопка «Фильтры» + `#filters-drawer`); поиск занимает всю ширину; **таблицы** (`ui-data-table`, `min-width:960px`) требуют горизонтального скролла на всех экранах (обращения/клиенты/шаблоны/вложенные таблицы карточки клиента) |

Отдельно отмечено (см. «Адаптивность» ниже): страницы «Клиенты»/«Шаблоны» не имеют выделенного brekpoint ≤768/390 для toolbar — фильтры просто переносятся построчно за счёт `flex-wrap: wrap`, без drawer-паттерна, в отличие от «Обращений».

## Общая оценка

Прототип визуально целостен на уровне отдельных экранов: новая токен-based система `ui-*` (кнопки, поля, бейджи, таблицы, карточки, модалки, drawer, tabs, timeline, meta-list) применяется последовательно на большинстве экранов (Обращения, Карточка обращения, Клиенты, Карточка клиента, Шаблоны, Аналитика, Настройки) и в целом соответствует зафиксированным design-токенам (`docs/design-tokens.md`) и предыдущим Figma-mapping документам.

Главные найденные проблемы — не про «сломанный» интерфейс, а про **согласованность**:

1. Экран создания обращения (`#/flow`) визуально «выпадает» из системы — использует старую (legacy) вёрстку `styles/main.css` с другим шрифтом и палитрой (см. UI-001).
2. Есть один явный markup/CSS-баг на карточке клиента (нестилизованный `dl`/`dt`/`dd`, см. UI-004).
3. Общий компонент модалки (`assign-modal`) не имеет части ожидаемых a11y-паттернов (Escape, focus trap, `aria-modal`) — UI-005.
4. Несколько мелких несоответствий высоты контролов (46px input/select vs 40px button) и цветовых пересечений бейджей — не критично, но заметно при внимательном сравнении.

P1-уровня (блокирующих демонстрацию) визуальных дефектов не найдено — что согласуется с выводом `docs/testing/release-readiness.md` («P0 нет, P1 DEF-002 исправлен»).

## Application shell

- **Sidebar** (`styles/layout/shell.css`): тёмный фон `--color-background-tabbar`, ширина 260px / collapsed 72px, nav item 44px, `is-active`/`hover`/`focus-visible` состояния — реализовано consistently, соответствует `docs/list-page-figma-mapping.md`.
- **Header** (`shell-header`): высота 72px, профиль справа, кнопка уведомлений с индикатором (`shell-header__badge-dot`) — кнопка не имеет обработчика (известный дефект, не дублируется), но сам индикатор **всегда видим** независимо от реального состояния — см. UI-006.
- **Collapse/expand sidebar**: сохраняется в `localStorage`, иконки/подписи скрываются корректно в collapsed-режиме.
- **Mobile drawer** (≤1024px): off-canvas сайдбар с overlay, корректная работа Escape/focus (`initMobileSidebar`), закрытие по клику на nav item — хорошо реализовано, см. `ui-preserve-list.md`.
- При переходе на `#/flow` ни один пункт навигации не подсвечивается активным (`navActiveMap` в `switchView()` не содержит ключ `flow`) — UI-002.

**Pre-existing изменение вне рамок этой задачи:** `styles/layout/shell.css` содержит незакоммиченные изменения (`git status` на момент начала аудита), сделанные **до** начала этого аудита в рамках отдельной предыдущей задачи (по описанию — закрепление sidebar/header). Эти изменения не создавались и не трогались в ходе данного аудита; они не описываются как дефект и оставлены как есть.

## Списки

### Обращения (`#/appeals`)
- Таблица (`ui-data-table`), toolbar (поиск + инлайн-фильтры + drawer на мобильном), loading/empty state, пагинация-заглушка — всё визуально согласовано с `docs/list-page-figma-mapping.md` и `docs/list-page-visual-check.md`.
- DEF-002 (поиск/фильтры) уже исправлен: код `filterAppealsList()` / `initAppealsListFilters()` подтверждает рабочую фильтрацию; итоговый UI toolbar визуально аккуратен, но есть неоднородность высоты контролов внутри одной строки (46px select/search vs 32px кнопка «Сбросить») — UI-003.
- Известные, не дублируемые дефекты, влияющие на визуальное восприятие: DEF-001 (колонка «Обновлено» = дата создания), DEF-007 (нет KPI над таблицей), DEF-009 (неполный список статусов в фильтре), заглушка пагинации «Страница 1 из 1».
- Таблица имеет `min-width: 960px` — на 1024/390 требует горизонтального скролла (UI-009).

### Клиенты (`#/clients`) и Шаблоны (`#/templates`)
- Обе страницы используют общий паттерн `ui-page__*` (page-layout.css) — заголовок, toolbar, состояния, таблица — идентичный визуальный язык, единообразные пустые состояния и бейджи статусов через `PageUtils.statusBadge`.
- В отличие от «Обращений», toolbar здесь **не имеет drawer-паттерна** для мобильных фильтров — элементы просто переносятся построчно (`flex-wrap: wrap` в `.ui-page__toolbar-row`). Работоспособно, но создаёт другой UX выбора фильтров на мобильном по сравнению со списком обращений — UI-007.
- Шаблоны: кнопка «Создать шаблон» задизейблена с tooltip-пояснением — хороший паттерн для «ещё не реализовано».

## Карточка обращения

- Двухколоночная сетка (`appeal-detail__grid`, main + sidebar 320px), корректно схлопывается в одну колонку на ≤1024px с `order:-1` для сайдбара (см. `docs/appeal-card-visual-check.md`).
- Header карточки: номер, заголовок, статус/приоритет/SLA-бейджи, метаданные, действия — визуально насыщенный, но читаемый блок.
- Статус/приоритет/SLA повторяются дважды — в header-бейджах и в блоке «Параметры обращения» сайдбара. Не критично (разный уровень детализации), но избыточно — UI-010 (косметика).
- Модалка назначения/переназначения исполнителя (`#assign-modal`) не имеет `aria-modal`, обработки Escape и focus-management — UI-005.
- Кнопки действий (`Принять в работу` / `Назначить исполнителя`, 40px) стоят в одной строке с `<select>` статуса (46px) — заметная разница высоты — часть UI-003.
- Вложения/комментарии/история — визуально аккуратны, состояния loading/empty присутствуют.

## Клиенты (карточка `#/clients/:id`)

- Header с бейджами, тегами, статистикой; двухколоночный layout (main + sidebar 320px), табы «Обращения/Документы/История» — соответствует `docs/client-card-figma-mapping.md`.
- **Найден markup/CSS-баг**: карточка «Контактная информация» в сайдбаре рендерится через `<dl class="ui-meta-list"><div class="ui-meta-list__row"><dt>…<dd>…` (`scripts/pages/client-detail-page.js`, `renderSidebar()`), но `styles/components/meta-list.css` стилизует только `.ui-meta-list__item/__label/__value`. Класс `.ui-meta-list__row` и голые `dt`/`dd` нигде не стилизуются → блок рендерится дефолтными браузерными стилями `dl` (отступы/интервалы отличаются от остальных списков в приложении) — UI-004.
- Известный функциональный дефект DEF-005 (SLA в таблице обращений клиента) создаёт видимую проблему — ячейка SLA показывает некорректное значение в этой же таблице; упомянуто как контекст, не дублируется как отдельный UI-дефект.
- Остальные блоки сайдбара («Связанные объекты», «Связанные договоры», «Важная информация») используют собственный класс `.client-detail__list-item` и стилизованы корректно.

## Адаптивность

Все выводы в этом разделе получены **исключительно статическим анализом `@media`-правил**, без визуального рендера в браузере.

- 1440/1280: полностью desktop-размётка на всех экранах, отличия только в ширине toolbar-контролов и количестве колонок KPI/настроек.
- 1024: единая точка перелома для сайдбара (off-canvas), карточек обращения/клиента (в одну колонку) и toolbar обращений (перенос строк). Согласовано между файлами.
- 390 (по факту наследуется от breakpoint 768 только в `appeals-list.css`): drawer-паттерн фильтров для обращений; для «Клиентов»/«Шаблонов» отдельного брейкпоинта нет — работает за счёт универсального `flex-wrap:wrap` (UI-007).
- `ui-data-table` имеет фиксированный `min-width:960px` во всех местах использования (обращения, клиенты, шаблоны, вложенные таблицы карточки клиента, таблица нагрузки в аналитике) → на 1024 и тем более 390 требуется горизонтальный скролл (UI-009).
- Модалка (`ui-modal__dialog`, `width:min(480px,100%)`) и drawer (`ui-drawer__panel`, `width:min(360px,100%)`) по CSS должны корректно помещаться на 390px с отступами `--spacing-5`; в браузере не проверено.

## Доступность

Проверено по коду (`aria-*`, `label`, `role`, `tabindex` в HTML; обработка `Escape`/фокус в JS):

- **Хорошо реализовано**: aria-label у большинства icon-only кнопок (закрыть меню, свернуть/развернуть сайдбар, обновить список, создать обращение, фильтры статуса/приоритета/исполнителя в toolbar), `aria-expanded`/`aria-controls` у переключателей сайдбара и drawer, `aria-hidden` у декоративных SVG, `role="dialog"` у модалки и drawer, `role="tablist"`/`role="tab"`/`aria-selected` в табах, Escape + focus return для мобильного сайдбара (`initMobileSidebar`) и для `#filters-drawer` (`initFiltersDrawer`).
- **Новые находки (не дублируют DEF-006)**:
  - `#assign-modal` не имеет `aria-modal="true"`, обработчика `Escape` и focus-management (фокус не переводится внутрь модалки при открытии и не возвращается на триггер при закрытии) — в отличие от `#filters-drawer`, где это реализовано. См. UI-005.
  - `#filters-drawer` также не помечен `aria-modal="true"` (только `role="dialog"`) — для экранных дикторов фоновый контент формально остаётся доступным при открытой панели.
  - Статус-select в карточке обращения обёрнут в `<label><span class="visually-hidden">Изменить статус</span><select aria-label="Изменить статус">` — одновременно визуально скрытый `<label>`-текст и `aria-label` на `<select>` (дублирование способа именования; не ошибка, но избыточно).
- DEF-006 (поле поиска обращений без accessible name) не дублируется, упомянуто только как контекст.

| `.ui-alert--error` | Карточка обращения (action/comment error), модалка назначения | Определён дважды с разными значениями padding/radius (`input.css` и `modal.css`); за счёт порядка подключения в `index.html` реально применяется всегда версия из `modal.css` — видимого расхождения между экранами нет, но дублирование правила — техдолг для будущих правок стилей (не заведено как UI-issue, см. пояснение выше) |

## Ограничения проверки

- **Живой браузерный рендеринг недоступен**: в среде агента нет Playwright/Puppeteer/DevTools и вообще браузерного движка — ни один экран не был визуально отрисован и сфотографирован в рамках этой задачи. Все выводы о layout, breakpoints и фактическом визуальном виде получены путём чтения HTML/CSS/JS-кода и логического применения CSS-каскада/`@media`-правил, а не наблюдением в браузере.
- Пункты, касающиеся конкретных разрешений (1440/1280/1024/390), явно помечены как **«проверено по коду, не воспроизведено визуально в браузере»** — см. разделы «Проверенные разрешения» и «Адаптивность».
- Папка `docs/testing/ui-screenshots/` **не создавалась** — реального способа сделать скриншоты в этой среде нет. Вместо скриншотов в реестре проблем (`ui-issues.md`) для каждого пункта указан точный маршрут (hash) и viewport для ручной проверки пользователем в браузере.
- Figma MCP (`plugin-figma-figma`) доступен, но точечный запрос `get_screenshot` (узел кнопок Kit, `3819:198`) был отклонён с ошибкой превышения лимита запросов тарифа Starter — повторных попыток в рамках аудита не предпринималось, чтобы не расходовать лимит впустую. Сверка с Figma выполнена по ранее сохранённым mapping-документам и `docs/design-tokens.md`, а не по новым прямым вызовам MCP в этой сессии.
- Аудит не включает функциональное тестирование (клики, ввод данных, сетевые запросы) — только статический разбор кода на предмет визуальных и структурных несоответствий. Известные функциональные дефекты (`docs/testing/defects.md`) не переисследовались и не дублируются; там, где они создают дополнительный видимый эффект, это отмечено в тексте со ссылкой на существующий Defect ID.
- Production URL (`https://appealhub.mararx.com/`) не открывался в рамках этой задачи — выводы применимы к текущему состоянию кода в рабочем дереве.
