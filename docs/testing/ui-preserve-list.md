# Что важно сохранить

> Составлено по итогам read-only UI-аудита (`docs/testing/ui-audit.md`, `docs/testing/ui-issues.md`). Все пункты проверены по коду; визуальный вид не воспроизводился в браузере, но соответствующие CSS/JS-решения зафиксированы явно и последовательно применяются.

| Экран | Компонент | Что работает хорошо | Риск регрессии |
|---|---|---|---|
| Application shell (все экраны) | Sidebar + collapse/expand | Тёмный сайдбар на токенах, плавный collapse (260px↔72px) с сохранением состояния в `localStorage`, корректное скрытие текстовых подписей в collapsed-режиме | LOW — изолированный CSS/JS-модуль (`initSidebarToggle`), не завязан на другие фичи |
| Application shell (≤1024px) | Mobile off-canvas drawer | Полноценный off-canvas сайдбар с overlay, Escape закрывает и возвращает фокус на кнопку-триггер, авто-закрытие при клике по пункту меню и при возврате на desktop-ширину (`matchMedia` listener) | MEDIUM — сравнительно сложная логика (`initMobileSidebar`), затрагивает несколько состояний; при рефакторинге легко сломать фокус-менеджмент |
| Список обращений | Toolbar поиск/фильтры (после DEF-002) | Единое состояние фильтров (`appealsListFilters`), синхронизация между inline-фильтрами и drawer-версией (`syncFilterSelects`), корректный empty state и счётчик найденных записей | MEDIUM — синхронизация двух наборов select (inline + drawer) — при добавлении новых фильтров нужно не забыть продублировать в обоих местах |
| Список обращений / Клиенты / Шаблоны | `ui-data-table` | Единообразная высота header (44px) и строк (56px), понятная hover-подсветка, muted-стиль для второстепенных колонок, `ui-data-table__id` с моноширинными цифрами для номеров | LOW — общий компонент, менять только централизованно в `table.css` |
| Обращения, Карточка обращения, Карточка клиента | `ui-status-badge` / `ui-priority-badge` | Консистентный pill-паттерн (высота 20px, radius pill), единая палитра status/priority на основе семантических токенов, переиспользуется во всех местах через `renderStatusBadge`/`PageUtils.statusBadge` | LOW — важно только не потерять источник правды (`status-catalog.js` → `variant`) при доработке цветов (см. UI-008) |
| Карточка обращения | Header карточки (номер + заголовок + бейджи + метаданные + действия) | Чёткая иерархия: номер → заголовок → статусные бейджи → метаданные (создано/обновлено/исполнитель) → основные действия; хорошо считывается на 1440/1280/1024 | MEDIUM — при схлопывании на ≤1024px порядок сохраняется корректно (`flex-wrap`), но при добавлении новых полей может потребоваться пересмотр `appeal-detail__meta-row` |
| Карточка обращения | История/лента событий (`ui-timeline`) | Разные визуальные маркеры для типов событий (`--internal`/`--client`/`--system`/`--user`, цветная левая граница, суффикс автора), понятная хронология с датой/временем | LOW — стилизация полностью в CSS через модификаторы класса, легко расширяется новыми `kind` |
| Карточка обращения | Комментарии и вложения (`ui-comment-form`, `ui-file-uploader`, `ui-file-item`) | Понятная форма с ограничениями (лимиты по типу/размеру/количеству явно выведены в UI), состояние "pending" для ещё не отправленных файлов, кнопка отправки с loading-состоянием и защитой от двойной отправки | MEDIUM — логика проверки (`AttachmentValidator`) и рендер выбранных файлов тесно связаны; при рефакторинге не потерять `renderSelectedFilesList` |
| Все экраны | Loading / Empty состояния (`ui-loader`, `ui-empty-state`) | Единый визуальный паттерн (спиннер + текст / иконка + заголовок + текст + опциональное CTA), применяется одинаково на 7 экранах через `PageUtils.setPanelState` | LOW — централизованный паттерн, изменения в одном месте отражаются везде |
| Аналитика | KPI-карточки (`analytics-kpi`) | Компактные карточки метрик с понятной типографикой (label + крупное значение), выделение проблемных значений через `--danger` модификатор (просрочено — красным) | LOW — самостоятельный CSS-блок, не пересекается с другими компонентами |
| Аналитика | Демо-нотис («Демонстрационные данные») | Прозрачная коммуникация о том, что данные не реальные — хорошая UX-практика для прототипа | LOW |
| Настройки | Каталог разделов (`settings-item`) | Понятная карточка с иконкой, названием, описанием и readiness-бейджем; disabled-состояние для PLANNED-разделов визуально отличимо (opacity + `not-allowed`) | LOW |
| Шаблоны, Карточка клиента | `ui-tabs` | Простой, доступный (`role="tablist"`/`role="tab"`/`aria-selected`) таб-компонент с чёткой активной подчёркивающей линией | LOW |
| Карточка клиента, Шаблоны | Disabled-кнопки с `ui-tooltip`-подсказкой («Будет реализовано отдельным этапом», «Файл недоступен в прототипе») | Хороший паттерн честной коммуникации об ограничениях прототипа вместо скрытия функциональности | LOW |
| Список обращений (мобильный) | Filters drawer (`#filters-drawer`) | Полноценная выезжающая панель с корректным Escape/backdrop/reset, синхронизация с inline-фильтрами при открытии/закрытии | MEDIUM — общий паттерн стоит перенести на другие списки (см. UI-007) осторожно, не потеряв текущую синхронизацию |
